# 密钥管理方案（团队 / 群 / 个人 / 本机）

> 状态：方案待拍板（2026-10-19，姜维川提出）。依据：需求规格 §7.3、§13、风险表第 6 条；`安全说明.md`。

## 1. 目标与边界

- 目标：Skill、MCP、Bot 用到的 token 只在平台维护一份。团队可以统一设置，也可以每人各填自己的；值不经过群消息、浏览器回显、日志和工作区。
- 第一个场景：`feishu-devops-cli` 技能要用的 `FEISHU_DEVOPS_TOKEN`（`fd` 已支持读这个环境变量，fd 本身不用改）。
- **做不到的事（写进文档和界面提示）**：Agent 能执行命令，注入进程的环境变量它一定读得到；跑 Bot 的那台机器的主人也读得到。平台能做的是缩小注入范围、输出打码、审计留痕，**不能**防住被诱导的 Agent 把值发到外网。所以只把「能交给 Bot 用」的凭据放进来，且尽量用权限最小的 token。

## 2. 现状与缺口（代码核实）

| 项 | 现状 | 问题 |
|---|---|---|
| 通用环境变量 | `run.start` 没有这个字段 | 没有注入通道 |
| MCP 密钥 | `mcp_servers.config` 里的 env/headers **明文**存放（`mcp/secrets.ts`） | 不加密；群管理员通过 `GET /groups/:id/inherited-mcp` 能读到团队层的值；没填的 `${secret:X}` 会原样下发 |
| 加密 | `lib/seal.ts`：AES-256-GCM，单把密钥，不能轮换 | 不支持轮换 |
| 打码 | `runs/redact.ts`：只认 `GONGGONG_REDACT_VALUES` 和常见 token 格式 | 不认数据库里存的密钥；服务日志（`service_logs`）、Agent 工具写入的内容不打码 |
| 供应商 Key | daemon 本机 `providers.json`；Claude 的覆盖配置文件落盘（0600，保留 7 天） | 和规格「团队密钥不落盘」冲突，团队密钥不能走这条路 |
| Agent 进程 | 每个「群 × Bot」一个 adapter 进程，跨轮次复用；换供应商时重启并接续原会话（`session.rs:991`） | 密钥变化可以复用这套重启机制 |

## 3. 核心模型：「定义」和「值」分开

**密钥定义**（team / group 层）：
- `name`：环境变量名，`^[A-Z][A-Z0-9_]{1,63}$`，例如 `FEISHU_DEVOPS_TOKEN`
- `description`：用途，也写怎么申请
- `mode`，三选一：
  - `shared`：只用统一值，个人不能覆盖。适合团队共用的服务 token（现在的 devops token 就是）
  - `shared_overridable`：有统一值，个人填了就用个人的
  - `personal`：每人各填自己的，没有统一值。适合个人 Jira、GitHub 这类，也是 devops 后端支持每人一个 token 之后的形态
- `bots`：哪些 Bot 可以拿到，默认全部，可以限定到指定 Bot（最小授权）
- `enabled`、`expiresAt`（可选，到期前提醒）

**值**（全部用 `seal()` 加密，存进去后谁都读不出明文，只显示「已填写 · 末 4 位 · 更新人 · 更新时间」）：
- 统一值：放在定义所在的那一层
- 个人值：按「用户 × 团队 × 名称」存，只有本人能写，管理员和系统管理员都读不到
- 本机值（三期）：只存在 daemon 本机（系统钥匙串），服务器只知道名字，对应规格 §7.3 的「个人密钥」

**取值优先级**（一次运行）：触发人的个人值（mode 允许时）> 群统一值 > 团队统一值 > 本机值。群层的同名定义覆盖团队层，规则和 MCP、Skill 一样。

> 和规格的差异，需要拍板：规格要求「个人密钥只在本人 daemon 上」。但 Bot 多半跑在别人的机器上，个人值只放本机的话，触发别人的 Bot 时就用不了。方案改成个人值也存在服务器（加密），每个值带一个开关「允许在他人机器上的 Bot 使用」，**默认关**：关着时只有本人机器上的 Bot 能注入，因为机器主人能读到进程环境变量，这一点要在界面上写明。

## 4. 下发与注入

1. 服务端组装 `run.start` 时，按「群 → 团队 → 定义 → `bots` 授权 → mode → 触发人」算出这次运行要注入的变量，新增字段 `env: Record<string,string>`（只放这次需要的，不全量下发）。
2. 运行记录新增 `secretNames`，只记名称和来源层，不记值。运行详情里显示「本次注入：FEISHU_DEVOPS_TOKEN（团队）」。
3. daemon 只在内存里持有，放进 adapter **进程环境变量**（Claude、Codex 都走这条路，不写进覆盖配置文件，不落盘）。Agent 的 Bash 工具、MCP 子进程都会继承。
4. 生效时机：把 env 的摘要算进 adapter 的启动签名。签名变了（值改了、换了触发人且个人值不同）就复用「换供应商」的机制，重启进程并接续原会话，群里的对话不中断。
5. daemon 不打印 `run.start` 的 env；诊断包按值打码（复用 `logs.rs` 的 `redact`）；token 被吊销时，内存里的值随进程一起清掉。
6. 传输：一期依赖 WSS。daemon 现在不校验证书，见 `安全说明.md`，这是已有的风险。三期每台机器生成密钥对，服务器用机器公钥加密后下发（规格「按机器加密下发」）。

## 5. Agent 侧

- 新增内置工具 `secret_list`：返回本群可用的定义、来源层、状态（已填写 / 缺失 / 已过期），**永远不返回值**。
- 新增 `secret_request`：缺值时在群里发「填写密钥」卡片。`personal` 卡片只有触发人能填；`shared` 卡片只有对应层的管理员能填。复用现在 MCP 的卡片流程，泛化成通用的密钥卡片。
- Agent 不能写值，也不能建定义（防止它把值写进定义描述）。
- Skill 在 frontmatter 声明自己要用哪些密钥（按 Agent Skills 规范放进 `metadata`，开工前核实格式）。运行前发现缺失就提示 Agent 调 `secret_request`，不会把运行跑挂。

## 6. 防泄露

- **打码**：`redact` 改成按运行生成，把这次注入的值，加上本群所有统一值，作为已知值打码（值短于 8 位的拒绝保存，避免误伤）。打码范围从「运行输出」扩到：
  - Agent 工具写入的内容：发消息、知识库、`skill_create`/`skill_update` 的文件、`mcp_create`、定时任务 prompt
  - 审批标题和详情、服务日志、附件名
- **工作区**：强制同步和提交前，扫描改动里是否出现已知值，出现就拦截。这是规格 §7.3「密钥不得落进工作区」的兜底。
- **读取权限**：所有接口都不返回明文。存进去之后，管理员也只能覆盖，不能查看。同时修掉 inherited-mcp 把明文暴露给群管理员的问题。
- **审计**：`secret.define / set / clear / delete / request` 写进审计记录，只记名称和层。每次注入记在运行记录上，可以按名称反查「谁、哪个 Bot、什么时候用过」。

## 7. 权限

| 操作 | 团队层 | 群层 | 个人值 |
|---|---|---|---|
| 建定义、改统一值 | 团队 owner / admin | 群管理员 | — |
| 填写个人值 | — | — | 仅本人 |
| 查看名称和状态 | 团队成员 | 群成员 | 本人；管理员只能看到「谁已填写」 |
| 读取明文 | 无人 | 无人 | 无人 |

## 8. MCP 统一（二期）

- MCP 的 env/headers 值统一写成 `${secret:NAME}`：服务端替换团队、群、个人的值，daemon 替换本机的值，仍然缺失的话这个 MCP 在本次运行中禁用，并在 Bot 状态里提示（规格 §7.3）。
- 迁移：现在明文存放的 MCP 值，自动转成群层或团队层的密钥（名称用 `MCP_<服务名>_<KEY>`），config 里改成引用，旧明文清掉。
- MCP 填写密钥卡片并入通用的密钥卡片。

## 9. 界面

- 团队设置新增「密钥」标签页（管理员）：定义列表、统一值、mode、授权 Bot、到期时间，个人值的填写情况（只显示人数和名单）。
- 群设置新增「密钥」标签页：显示继承的定义和来源层，可以在群层覆盖。
- 个人设置新增「我的密钥」：按团队列出要求本人填写的定义，可以填写和清除，有「允许在他人机器上的 Bot 使用」开关。
- 桌面端 / `gg secret`（三期）：本机值。
- 输入框全部用 `SecureField`，存完不回显。

## 10. 分期

| 期 | 范围 | 验收 |
|---|---|---|
| 一期 | 定义 + 统一值 + 个人值（加密）；`run.start.env` 和 daemon 进程环境变量注入；按运行打码（含工具写入）；`secret_list`/`secret_request` 和卡片；三处界面；审计和运行记录里的密钥名；`feishu-devops-cli` 技能改成读环境变量 | Bot 不配本机 token 也能 `fd build`；值不出现在消息、运行详情、日志、知识库；改值后下一轮生效且会话不中断 |
| 二期 | MCP 统一用 `${secret:}`，迁移现有明文；修掉 inherited-mcp 泄露；Skill 声明密钥并做缺失检查；工作区和强制同步扫描已知值；服务日志打码 | 现有 MCP 无感迁移；群管理员读不到团队层 MCP 值 |
| 三期 | 本机密钥（系统钥匙串 + `gg secret`）；按机器加密下发；数据密钥轮换（信封加 `kid`，配重加密工具）；到期提醒 | — |

一期涉及：数据库迁移（新增 2 张表，`runs` 加 1 列）、协议（`run.start.env` 加 fixture）、daemon、server、web、desktop。属于需要先确认的大功能。

2. 授权范围：默认对全部 Bot 开放，可以限定到指定 Bot。还是默认只开放给声明了这个密钥的 Skill 所在的运行？
