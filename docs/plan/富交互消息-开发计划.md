# 富交互消息（Rich UI）开发计划

> 状态：已拍板，待开工（2026-10-22，姜维川提出并确认第 7 节）。

## 1. 目标

让 Bot 在一条回复里，除了 Markdown 文本，还能给出图表、指标卡、流程图/架构图、时间线、表格，以及可点击的按钮和选项。必要时还能嵌入一个可交互的 HTML 小页面。形成「Agent 输出结构化块 → 校验 → 前端组件渲染 → 用户操作回到 Agent」的闭环。

**不做**：不让模型输出的任意 HTML 进入主页面 DOM；不替代现有的预览（`preview_expose` / `preview_static`，适合完整网页或应用）。

## 2. 现状与约束

| 项 | 现状 | 对方案的影响 |
|---|---|---|
| Bot 回复 | Claude Code / Codex 经 ACP 产出文本，Web 用 `react-markdown` + GFM 渲染（`features/chat/Markdown.tsx`）；原始 HTML 不渲染 | 结构化块走 Markdown 围栏代码块最自然，**两种 agent 都不需要改造** |
| 结构化卡片 | 已有工具驱动的卡片：`progress_card`、提问卡片、预览卡片（消息 meta + `message.edited` 原地更新） | 需要「之后还会更新」的组件走工具；一次性的可视化走 Markdown 块 |
| 图表 | `ui/chart.tsx` 只有 Sparkline / TrendChart；没有图表库、Mermaid、KaTeX | 需要引入依赖，必须按需懒加载，不能拖慢首屏 |
| 隔离的 HTML | 预览系统已有独立子域（`*.preview` 域名）和静态托管 `preview_static` | HTML Widget 可以复用独立域名做 origin 隔离 |
| 飞书镜像 | Bot 回复同步到飞书卡片（markdown 元素） | 每种块都要有飞书降级：文字摘要，加「在共工查看」链接 |
| 桌面端 | 复用 web 组件 | 一处实现两端可用 |

## 3. 方案：分三层，按需取用

### 层 1：Markdown 扩展块（Schema 驱动，主路线，约 80% 的场景）
Bot 在回复里写带语言标记的围栏代码块。前端按语言查**组件注册表**渲染；内容用 zod 校验，**不合法时原样显示为代码块**，不会报错也不会空白。

| 语言标记 | 内容 | 渲染 |
|---|---|---|
| `mermaid` | Mermaid 源码 | 流程图、时序图、架构图、甘特图（懒加载 mermaid） |
| `chart` | JSON：`{type: line/bar/area/pie, title, x, series[], unit}` | 图表（懒加载图表库），悬停看数值，可切换系列 |
| `metrics` | JSON：`[{label, value, unit, delta, trend[]}]` | 指标卡一行，可带 Sparkline |
| `timeline` | JSON：`[{time, title, detail, status}]` | 时间线 |
| `math` / `$$` | LaTeX | 公式（懒加载 KaTeX，二期） |
| 表格 | GFM 表格（已支持） | 增强：超宽横向滚动，可复制为 CSV |

- **流式**：块没闭合之前按普通代码块显示（灰底占位）。闭合并且校验通过后才挂载组件，避免渲染半截 JSON。
- **契约**：所有块的 zod schema 放在 `packages/protocol/src/ui-blocks.ts`，Web 渲染、飞书降级、给 Agent 的说明都从这里生成，三处不会对不上。
- **教 Agent 用**：内置一个平台层 Skill `rich-ui`（复用现有 Skill 下发），写明每种块的格式、何时使用、数据量上限。所有 Bot 默认可用，群可以关闭。
- **飞书**：`mermaid` / `chart` / `timeline` 降级成一行摘要（标题 + 关键数值），加上「在共工查看图表」链接；`metrics` 转成飞书卡片的 markdown 列表。

### 层 2：可交互组件（按钮、选项、表单）
- 新增块 `actions`：`{prompt, options:[{label, value, style}], multiple?}`，渲染成一组按钮或多选。
- **点击 = 以点击人的身份回复这个 Bot**：在群里发一条引用这条回复的消息，正文是 `@Bot 选择了「xxx」`，触发下一轮；不另建交互通道，权限、审计、飞书同步都沿用现有消息流程。
- 已经点过的组件显示「张三 已选择 xxx」，防止重复点。状态存在消息 meta，用 `message.edited` 推送。
- 需要「等人回答后同一轮继续」的场景，继续用已有的 `ask_group_members` 提问卡片，层 2 不重复造。
- 组件内部的筛选、切换（图表切系列、表格排序）纯前端处理，不回 Agent。

### 层 3：HTML Widget（高自由度，约 20% 的场景）
- 新增块 `html`：Agent 直接写一段自包含的 HTML/JS（内联 CSS/JS，不引外链脚本）。
- **隔离**（实施时简化，2026-10-22）：不经服务器托管，Web 直接用 `<iframe sandbox="allow-scripts" srcdoc>` 内嵌，不给 `allow-same-origin`，iframe 是不透明源，拿不到 cookie、本地存储和主站 DOM。HTML 最前面注入 CSP meta：`default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:`，**禁止联网**，数据只能写在 HTML 里。这样不依赖预览域名配置，也不需要新的附件类型。
- **桥接**：用 `postMessage` 提供最小 API：`gg.resize(height)`（自适应高度）、`gg.reply(text)`（等同层 2 的点击回复，需要用户点击触发）。不提供读取群消息等能力。
- 限制：单个 Widget ≤ 512 KB，默认折叠为预览卡，点开再加载，避免一条消息里塞多个重页面拖垮时间线。
- 飞书：显示「交互页面 · 在共工打开」链接卡片。

## 4. 技术选型（待确认）

| 用途 | 推荐 | 理由 |
|---|---|---|
| 图表 | **ECharts（按需引入，懒加载）** | 图表类型全、交互完善、深浅色主题好适配；约 300–400 KB gzip，仅在出现 `chart` 块时加载 |
| 图表（备选） | 继续扩展自研 `ui/chart.tsx` | 零依赖、风格统一，但折线/柱状/饼图以外的类型都要自己写 |
| 流程图 | Mermaid（懒加载） | 业界默认，Agent 最熟悉 |
| 公式 | KaTeX（二期，懒加载） | 体积小、渲染快 |
| 校验 | zod（已有） | 与协议包一致 |

新依赖引入前按仓库规定用 `npm view` 核实版本并查官方文档。

## 5. 分期

| 期 | 内容 | 规模 | 涉及 |
|---|---|---|---|
| 一期 | 组件注册表与 `ui-blocks` 契约；`mermaid`、`chart`、`metrics`、`timeline` 四种块；流式闭合后挂载；校验失败降级为代码块；飞书降级；平台 Skill `rich-ui` | M | protocol、web（desktop 复用）、server（飞书降级） |
| 二期 | `actions` 交互块（点击即回复 Bot、已选状态）；表格增强；KaTeX | S–M | protocol、web、server（点击回复接口与状态） |
| 三期 | `html` Widget：独立域托管、沙箱 iframe、CSP、`postMessage` 桥、折叠预览 | M | server（存储与托管）、web、预览域配置 |

都不需要改 daemon 和 agent，不发客户端版本就能上线；三期可能新增附件类型，但不需要加表。

## 6. 验收要点
- 每种块：合法渲染、非法降级、流式中途不闪错；深色/浅色主题；手机端宽度自适应。
- 首屏包体不增加（新依赖都懒加载，用打包产物体积测试兜底）。
- 安全：HTML Widget 读不到 cookie 和主站 DOM、不能联网、不能自动触发回复（必须用户点击）。
- e2e：mock agent 输出含 `chart` + `actions` 的回复 → 渲染 → 点击按钮 → 触发下一轮。
