# 插件体系方案（open-design 融入）

> 状态：方案已评审（2026-10-20，姜维川）；P0 验证进行中，P1 起未开工。原型：`docs/原型UI-AI 对话 agent系统界面设计方案/插件与创作/index.html`（地址后加 `#entry` `#sheet-0` `#ask` `#result` `#review-0-annot` `#manage` 可直达对应场景）。

## 1. 结论与边界

- open-design（下称 OD，nexu-io/open-design，Apache-2.0）是单用户、本地优先的完整产品（Next.js + Express/SQLite daemon + Electron），不是组件库。**只取它的文件格式和内容，不嵌入它的运行时**：
  - 文件格式：`SKILL.md`、`DESIGN.md` + `tokens.css`、`open-design.json` 的一部分字段；
  - 不嵌入的原因：单用户、没有多租户；Claude 一律用 `bypassPermissions` 启动，会绕过我们的审批；MCP 依赖本机 daemon，而且没有鉴权；PDF/PPTX 导出绑定 Electron。
- 插件宿主由我们自己做，复用团队 Skill 的三层下发链路（平台 / 团队 / 群）。
- 插件是**叠加能力**：系统总开关关闭、或者群里没有启用任何插件时，界面、数据、下发内容、提示词、上下文占用都和现在一致。

## 2. 插件模型

- 插件 = 一个目录 + 一份清单，内容可以是 skills、设计系统（`DESIGN.md` + `tokens.css`）、MCP、所需密钥、输入参数。以后再扩展产物渲染和导出。
- 清单兼容 `open-design.json` 的子集：`name`、`version`、`title`、`inputs`、`od.kind/mode`、`compat.agentSkills`。另外加三项我们自己的字段：`agents`（支持 claude / codex）、`minDaemon`（最低机器版本）、`secrets`（声明需要的密钥）。OD 包由导入器单向转换，不承诺反向兼容。
- 作用域：平台层（官方市场）→ 团队安装并固定版本 → 群启用或关闭；群级关闭继承项沿用 `group-overrides`。
- 官方插件内置在服务端，启动时自动装到平台层，不需要上传，群管理员在群里打开即可用（2026-10-22）。
- 存储：清单和小文件放数据库；字体、图片等大资源放文件存储，按摘要缓存。现有 Skill 只能存 5MB 的 jsonb，放不下这些。

## 3. 兼容性改造（装与不装的影响）

| 现有能力 | 处理 |
|---|---|
| 团队 Skill | 每个插件下发成一个独立的 Claude 插件目录，名字形如 `<插件>:<skill>`，`gonggong-team` 不动。Codex 用软链，名字自动加前缀；安装时检查是否重名 |
| 会话 | 启用、停用插件都在下一轮生效，不打断正在运行的任务（skill 名单变化会重启 adapter 并接续会话） |
| 系统提示词 | 只有群里选了设计系统才注入；超过上限时改为按需读取文件 |
| MCP / 密钥 | 并入现有三层 MCP，保留名不可用；缺密钥时这一轮不下发该插件，复用填写密钥卡片 |
| 权限 | 插件不能提高 Bot 的权限档位；一期不支持 hooks 和可执行的 MCP；执行命令仍走审批 |
| 机器版本 | daemon 遇到不认识的字段会直接忽略，服务端也没有按功能区分版本（已核实）。**新增 daemon 能力上报**：旧版本机器不下发插件，界面写明「机器版本过低」 |
| Agent 种类 | 插件声明支持的 agent；不支持的 Bot 在入口里置灰并说明原因 |
| 消息卡片 | 新增可选的通用字段 `card: {type, version, data}`，同时带纯文字摘要，旧客户端和飞书显示文字加链接。现有的预览、进度、密钥卡片先不迁移 |
| 停用 / 卸载 / 升级 | 产物快照存在服务端，停用后仍可查看，卡片变只读；产物记录生成时用的插件版本 |
| 桌面端 | 只做插件管理，不做创作 |
| 数据库迁移 | 只新增表或字段，可以回滚；插件关闭时跑全量测试，结果应与改动前一致 |

## 4. 交互（已拍板）

- **入口**：「✦ 创作」放在输入框工具栏，只有本群启用了插件才显示。群头部只展示「插件 · N」和当前设计系统。`/` 候选里加一个「插件」分组。
- **创作面板，4 步**：类型与模板 → 设计系统 → 内容与参数 → 交给谁。
  - 表单按插件的 `inputs` 生成；
  - 不满足条件时当场处理：版本过低、离线、不支持的 Bot 选不了；缺密钥就地填写；
  - 右侧显示「将交给 AI 的内容」。
- **创作请求卡片**：只显示摘要（模板 · 设计系统 ·「标题」）和「查看全部」，可以「再来一版」或「改参数重做」。服务端把选项转成结构化指令后 @ Bot。
- **产物卡片**：原地更新（生成中 → v1 → v2），带缩略图、版本号，以及这一版改了什么。可以预览、批注、再改、换设计系统、定稿、导出。
- **工作台**：切换版本、和上一版对比、调整视口宽度、看谁在看。批注**按版本隔离**，锁定在「版本 + 元素」上并附截图，不往新版本迁移。可以带着未解决的批注 @ Bot，新版本出来后自动刷新。

## 5. AI 提问卡片（设计增强）

- 沿用现有的「向群成员提问」（`ask_group_members`，Claude 和 Codex 都能用），不另做一套。Claude 自带的 AskUserQuestion 没有接入群聊。
- 协议改动：在 `Question.options` 的每一项上加三个可选字段：
  - `image`：产物文件或缩略图；
  - `swatch`：色值数组；
  - `description`。

  这些字段都不填时，和现在完全一样。
- 选项内容由插件或设计系统提供，界面由宿主统一渲染：
  - 色板取当前设计系统的 tokens；
  - 插件可以声明常问的问题（例如落地页问主色、首屏内容），面板里已经填过的不再问；一次创作最多问一两轮。
- **视觉方向**：只有在面板里打开「先出 2–3 个视觉方向」时才生成草图，并作为第 1 题；默认关闭。
- **倾向**：其他成员可以给选项点「倾向」，头像显示在选项下，**只供参考，不算投票**。提交人仍是发起人或 Bot 主人，超时按推荐项继续。
- 降级：飞书和旧客户端显示纯文字题目，加「在共工里回答」的链接。

## 6. 产物与预览联动

- 新增「产物」实体：属于某个群和某个插件，记录用了哪个设计系统；每个版本是不可变的文件快照，带缩略图和来源运行。每轮结束时由 daemon 上传快照，所以机器离线也能看、能对比，也能按版本分享。
- 只给存在服务端的静态产物注入桥接脚本，放在独立预览域名下，双方都校验 origin（OD 用的是 `'*'`，不能照搬）。桥接支持：圈选批注、PPT 翻页联动、参数面板、新版本推送。
- 前置修复：端口模式下，`previews/access.ts` 的 `foreignCookies` 只剥掉了 `gg_pv_*`，`gonggong_session` 会被转发给 Bot 本机的服务。

## 7. 合规

- Apache-2.0 要求保留版权和许可声明。
- `guizang-ppt` 上游已改为 AGPL-3.0，只能用 OD 内的 MIT 旧版，不能跟随上游更新。
- 72 个提示词模板是 CC-BY-4.0，需要署名，并替换第三方热链。
- 不收录真实品牌命名的设计系统（Apple、Stripe、Tesla 等，指定了专有字体）。只用中性风格和团队自建的设计系统。
- 不 fork OD 代码，按固定版本快照导入，人工审核。
