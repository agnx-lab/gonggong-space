# Git 管理对标 IntelliJ IDEA — 开发计划

姜维川 2026-10-23 提出：Git 查看与管理的功能和界面都对标 IntelliJ IDEA 补齐细节，做到美观、完善可用。

## 决策（姜维川 2026-10-23 拍板）

1. **允许安全强推**：`--force-with-lease`，仅限非基准分支；主人二次确认，非主人申请需主人审批。受保护的基准分支永远不能强推，也不能在远程删除。
2. **危险操作**（重置 --hard、回滚改动、强制检出、删除本地/远程分支、删除贮藏、强推）：主人弹窗二次确认后执行；非主人照旧提交申请、主人审批。
3. **群通告**：所有成功的写操作都发群事件（与现在一致），只有逐个文件的「解决冲突」不发。
4. **交付**：自检全绿 + 界面截图发群确认后再推送；daemon 新版交给共字君codex 发布。

不变的约束：运行中禁止写操作；非主人发起的写操作需主人审批（30 分钟过期）；读操作群成员都可用。

## 架构

- **协议**（`packages/protocol`，本计划 C0）：daemon 能力 `gitOps3`。新读消息 `git.changes` / `git.show` / `git.blame` / `git.stashes` / `git.conflict`；`git.log` 加 `filter`；`git.diff` 加 `ignoreWhitespace` / `context`；所有 git 读加 `repo`；`git.refs` 结果加 `tags` / `recent`；`GitStatus` 加 `head` / `ongoing` / `conflicts` / `stashes`。写操作 `GitActionKind` 扩到 23 种，`branch` / `remote` / `message` / `paths` 沿用，其余参数放 `args`（`GitActionArgs`）。REST 见 `web.ts` 的 Git 段，请求体 `GitActionReq` 按操作区分校验。
- **数据库**：`git_operations.args jsonb`（迁移 0079）。
- **daemon**（`git_ops.rs`）：读操作不碰索引与工作树；写操作全部经目录占用检查，提交类操作带 Bot 身份，`GIT_EDITOR=true` 不开编辑器；产生冲突时报失败并保留冲突状态，状态栏横幅引导解决。
- **服务端**：`featureFor` 按操作与参数要求 `gitOps3`；`/git/changes` 对旧 daemon 退化为 compare（`limited`）；强推与远程删除基准分支直接拒绝；新操作的群事件用通用文案 `{user} 在 {bot} 的工作区执行了 {summary}`。
- **Web**：Git 标签页（提交 / 贮藏 / 记录 + 工具条、分支弹窗、冲突横幅）、提交历史标签页（分支面板 + 提交图 + 筛选 + 详情）、新增「比较」「合并冲突」标签页；对话框统一放 `features/git/dialogs`，操作入口统一走 `useGitCommands`。

## 验收

- 每个写操作：主人直接执行、非主人申请审批、运行中 409、旧客户端 409「版本过旧」；危险操作有二次确认。
- 冲突全流程：合并产生冲突 → 横幅 → 三方合并解决 → 继续 → 群事件。
- 界面：亮 / 暗主题、窄屏（手机）与宽屏都可用；截图发群确认。
- `pnpm check --all` 全绿，e2e git 用例通过。
