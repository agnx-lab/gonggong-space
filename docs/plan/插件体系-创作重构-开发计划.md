# 插件体系 · 创作重构开发计划

> 状态（2026-10-23）：已实现，分支 `feat/plugin-creation-rework`。偏离计划之处：
> - 「产品原型」的 44 个模板都保留设计系统：入口 skill 约定所有颜色和字体都取自 tokens，线框图也只从中取强调色和字体。所以内置插件暂时没有用到 `designSystem: false`，只按分组配置了输入项，并新增「页面清单」。
> - 「不用了」的接口是 `POST /api/groups/:id/creation-drafts/:messageId/dismiss`，没有用通用的 PATCH。
> - e2e 还发现时间线的 `message.edited` 没有同步 `card` 字段，已一并修好。
>
> 姜维川 2026-10-23 提出，方案已拍板：大弹窗；步骤按清单自动推导、模板可覆盖；对话调用走 Skill + MCP，AI 先发确认卡再开工；一次做完再推。不涉及数据库迁移；新增 MCP 工具需要发 daemon 新版（交给共字君codex 发布）。

## 现状问题

1. 面板固定为 940×540，53 / 44 个模板和 56 套设计系统挤在小格子里。
2. 步骤写死为 4 步：「幻灯片」没有设计系统，也要走一遍「设计系统」步；输入项是插件级的，线框图、移动应用、报告等模板需要的参数不同，却只能用同一份表单；只有一个 Bot 时也要专门走「交给谁」一步。
3. 群里启用插件后，skill 已经下发给 Bot，说「做个 PPT」能触发 skill。但 AI 不知道本群有哪些模板和设计系统，产出也不会生成创作卡片，后续的「再来一版」「改参数」都用不了。

## A · 面板尺寸（web）

- `CreationSheet` 宽改为 `min(1200px, 92vw)`，`.plg-sheet` 高改为 `min(820px, 100dvh - 120px)`；三栏改为 200px / 1fr / 280px。
- 模板缩略图网格 `minmax(180px, 1fr)`，设计系统卡片 `minmax(200px, 1fr)`。
- 手机端（≤ 640px）全屏，步骤条横排。

## B · 动态步骤

**协议**（`packages/protocol/src/plugins.ts`）只新增可选字段，旧清单行为不变：
- `PluginTemplate.inputs: string[] | null`：这个模板使用的输入项 id，从 `manifest.inputs` 里选（上传时校验 id 存在）；null 表示全部。
- `PluginTemplate.designSystem: boolean`，默认 true：模板自带视觉体系时为 false。
- 新增共享函数 `creationSteps(manifest, template, usableBotCount)`，web 用它渲染步骤，server 用同一套规则校验：
  - `template`：总是显示（选插件和模板）；
  - `design`：插件有设计系统，并且当前模板没有关闭设计系统时才显示；
  - `content`：总是显示（输入项按模板过滤，另有附件和视觉方向）；
  - `bot`：可用 Bot 多于 1 个时才显示。只有 1 个时自动选中，最后一步的主按钮写「交给 {bot}」，右栏显示 Bot。
- 切换模板后重新计算步骤；当前步骤消失时，跳到相邻的步骤。

**服务端**（`creations.ts`）：
- 模板关闭设计系统时，`designSystemId` 必须为 null；
- 只校验模板选中的输入项是否必填；
- 不属于该模板的输入项一律丢弃；
- 给 agent 的指令里不写设计系统那一行。

**内置插件**：
- 「幻灯片」不改清单，没有设计系统时自动跳过这一步；
- 「产品原型」按模板分组配置 `inputs`，线框图等模板设 `designSystem: false`，按需补充「页面清单」等输入项；
- 两个插件都升小版本号。

## C · 对话调用（Skill + MCP）

**新工具**（`packages/protocol/src/tools.ts` → `gonggong-tools.json`，服务端实现放在 `agent-tools/plugins.ts`）：
- `plugin_catalog({ plugin? })`
  - 不传 `plugin`：列出本群启用的插件（name、标题、简介、模板数、设计系统数），以及当前 Bot 能不能用（blocker）。
  - 传了 `plugin`：返回模板（id、标题、简介、分组、该模板的输入项、是否用设计系统）、设计系统（id、标题、分类、色板）和输入项定义。
  - 总开关关闭，或本群没有启用插件时，返回空列表并说明原因。
- `creation_propose({ plugin, template, designSystem?, inputs, directions?, note? })`
  - 校验规则复用 `createCreation`（抽出共用函数），允许必填项留空，卡片上标出「待补充」。
  - 以 Bot 身份发一条消息，消息 `card` 为新类型 `creation-draft`：内容是草稿，`status` 取 pending / started / dismissed；body 是纯文字摘要，飞书和旧客户端显示这段文字。
  - 返回给 AI 的结果：「已发确认卡，等成员确认；确认后会收到正式创作指令，在此之前不要开工。」

**确认卡**（web，`TimelineItems` 里渲染）：
- 「开始」：按草稿调用 `POST /api/groups/:id/creations`，由点击的成员发起，Bot 就是提出草稿的那个。成功后把草稿卡改为 started 并附上创作卡链接，后面走现有的创作流程。
- 「改参数」：打开 `CreationSheet`，用草稿预填（复用 `open.draft`）；提交后同样把草稿卡标为 started。
- 「不用了」：标为 dismissed。
- 新接口 `PATCH /api/groups/:id/messages/:mid/card`，只允许改状态，群成员可用。状态变化原地更新消息，参照进度卡。

**Skill 与提示词**：
- 群里启用了插件时，在上下文里加一行：本群启用了哪些插件；收到创作需求时先用 `plugin_catalog` 查，再用 `creation_propose` 发确认卡。
- 没有启用插件时不加，保持叠加能力的原则。
- 两个内置插件的入口 SKILL.md 补一段：
  - 对话里的需求（不是创作请求卡片）走 catalog → propose；
  - 收到正式创作指令后才出稿；
  - 工具不存在（daemon 版本较旧）时，直接按 skill 出稿。

**daemon**：工具清单是编译时嵌入的，新工具要发新版才会出现。代码合并后交给共字君codex 发版，附上 release notes。

## 测试（TDD）

- protocol：`creationSteps` 的条件矩阵；模板覆盖字段的解析与默认值。
- server：上传时校验模板 `inputs` 的 id；创作时按模板过滤输入项和设计系统；`plugin_catalog` 在开关和启用状态下的返回；`creation_propose` 发出确认卡；草稿卡状态流转和权限。
- web：「幻灯片」显示 3 步，「产品原型」显示 4 步；切换模板后步骤变化；只有一个 Bot 时并进最后一步；确认卡的三个按钮。
- daemon：工具清单的往返测试，`tools/list` 里包含新工具。
- e2e：`plugins.spec` 增加一条用例——mock agent 调用 `creation_propose`，成员点「开始」，断言出现创作卡并触发运行。
