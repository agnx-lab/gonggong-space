## 插件包布局

```
<plugin>/
├── gonggong-plugin.json        清单（PluginManifest）
├── NOTICE.md                   来源与许可（第三方内容必须有）
├── previews/<template>.png     可选，模板缩略图
└── skills/<entry>/SKILL.md     入口 skill；设计系统放在 skills/<entry>/<designSystems[].dir>/{DESIGN.md,tokens.css}
```

- **Claude**：daemon 把整个目录作为一个 Claude 插件加载（自动生成 `.claude-plugin/plugin.json`，`name` 为插件名），skill 显示为 `<插件名>:<skill>`。
- **Codex**：在 `<cwd>/.agents/skills/<插件名>-<skill>` 建软链。

## 切片

### S · 服务端（apps/server）
1. **迁移**（只新增表和字段）：
   - `plugins`：层、teamId / groupId、name、当前 versionId；
   - `plugin_versions`：files jsonb、manifest jsonb、digest、size、revision；
   - `group_plugins`：groupId、pluginId、enabled。
   - 同一层里 `name` 唯一；同名插件在层间合并，下层覆盖上层。
2. **上传校验**：必须有 `gonggong-plugin.json`，而且能通过 `PluginManifest`；`skills/<entry>/SKILL.md` 必须存在，frontmatter 复用 skills 的 `frontmatter()`；每个 `designSystems[].dir` 下必须有 `DESIGN.md` 和 `tokens.css`，模板的 preview 文件必须存在；路径规则、大小和数量上限沿用 skills。内容相同时不生成新版本。
3. **路由**：
   - 管理：`/api/{platform|teams/:id|groups/:id}/plugins` 的增删查（权限同 skills 三层）；
   - 文件读取：`GET /api/plugins/:id/files/*`，给模板缩略图用，要求有读取权限，带 nosniff 和 CSP sandbox；
   - daemon 拉文件：`GET /api/daemon/plugins/:versionId`（机器 token，只能拉本机 Bot 在本轮实际下发的版本，参照 skills）；
   - 群开关：`GET /api/groups/:id/plugins`、`PUT /api/groups/:id/plugins/:pluginId`，仅群管理员可改。
4. **总开关**：`SystemParams.pluginsEnabled` 默认 false。关闭时上面的群级路由返回空列表或 403，scheduler 不下发任何插件。
5. **下发**（`runs/scheduler.ts`）：同时满足以下条件的插件放进 `RunStart.plugins`：
   - 总开关开启，且本群启用了该插件；
   - Bot 的 agent 在 `manifest.agents` 里；
   - 机器的 features 含 `plugins`，并且 daemonVersion ≥ `minDaemon`；
   - 所需密钥在这一轮都能解析到（复用 `secrets/resolve.ts`）。

   计算 `GroupPluginDto.bots[].blocker` 和这里用同一个函数。
6. **创作**：`POST /api/groups/:id/creations`。
   - 校验：插件在本群已启用，模板和设计系统属于该插件，必填项已填，Bot 在群里且 blocker 为 null。
   - 以发起人身份发一条消息：mentions 指向 Bot，`card` 是 `CreationCard`，存进消息 meta（参照 progress 卡），附件照常挂上。
   - body 是给 agent 的指令（不翻译），内容包括：用哪个 skill（同时写出 Claude 和 Codex 两种名字）、模板、设计系统目录、是否先出视觉方向、参数清单，以及「产物写到 `design/<slug>/index.html`，完成后用 preview_static 发布」。
7. **倾向**：`POST /api/runs/:runId/questions/:setId/leanings`，同一选项再点一次即取消。只有题目在 pending 状态、调用者是群成员才可以。实时推送题目更新，`QuestionSetDto.leanings` 带上姓名。
8. **测试**：上传校验、三层合并、群开关、下发条件矩阵（4 种 blocker）、总开关关闭时零下发、创作消息与卡片、倾向。另外跑一遍回归：总开关关闭时 RunStart 和现在相同。

### D · daemon（crates/gonggong）
1. `protocol.rs` 同步：`RunStart.plugins`、`PluginRef`、`Question.option_meta`（serde 用 camelCase，缺省为空）。往返测试要覆盖三个新 fixture。hello 的 features 加上 `plugins`。
2. **安装**（`skills.rs` 旁新增 `plugins.rs`）：按 digest 增量拉取，写到 `~/.gonggong/plugin-sets/<name>-<digest>/`，并生成 `.claude-plugin/plugin.json`。
   - Claude：每个插件作为一项加进 `_meta.claudeCode.options.plugins`，与 `gonggong-team` 并列。
   - Codex：在 `.agents/skills/<name>-<skill>` 建软链（Windows 上复制），并写入 `.git/info/exclude`。插件被移除时把软链清掉。
   - 插件名单或 digest 变化：和 skills 一样重启 adapter 并接续会话，下一轮生效。
3. **ask_group_members**：工具 schema 增加可选的 `option_meta`，parse 时按下标对齐、截断并校验，然后原样放进 `QuestionAsk`。描述里写清楚：image 是工作区相对路径，swatch 是 6 位色值。
4. **测试**写在 `tests/it/`：安装、增量更新、移除清理、Codex 软链、Claude 插件列表、名单变化触发重启、`option_meta` 解析。

### W · Web（apps/web，desktop 复用的组件同时检查）
1. **插件管理**：
   - 平台、团队、群三层上传和删除，仿照 `config/SkillLayer.tsx`，支持文件夹或 zip，展示清单信息（版本、支持哪些 agent、需要的密钥、许可与来源）；
   - 群设置「插件」页：启用开关，按 Bot 显示可用性和原因，文案对照原型 `#manage`；
   - 系统设置加上总开关。
2. **创作入口**：
   - 只有总开关开启、且本群至少启用了一个插件时，输入框工具栏才显示「✦ 创作」；
   - 群头部显示「插件 · N」；
   - `/` 候选里加「插件」分组，选中后打开面板并预选该类型。
3. **创作面板**（Sheet，4 步，对照原型 `#sheet-0`~`#sheet-3`）：
   - 1 类型与模板（缩略图走插件文件接口）
   - 2 设计系统（色板）
   - 3 内容与参数（按 inputs 生成表单、附件，以及「先出 2–3 个视觉方向」开关）
   - 4 交给谁（不可用的 Bot 置灰并写明原因）
   - 右侧是摘要和检查结果；点「交给 AI」调用 `POST creations`。
4. **创作请求卡片**：时间线里遇到 `message.card.type === 'creation'` 时渲染摘要卡（模板 · 设计系统 ·「标题」+「查看全部」），提供「再来一版」（同参数直接再发一次）和「改参数重做…」（打开面板并预填）。未知的 card 类型照常显示 body。
5. **提问卡片增强**（`runs/QuestionBlock.tsx`）：
   - 有 `optionMeta` 时，选项渲染成卡片：缩略图（走工作区文件接口）、色板、说明；
   - 每个选项下显示倾向头像和「倾向」按钮，所有成员都能点；文案「其他人的倾向仅供参考，不算投票」；
   - 没有 `optionMeta` 时，界面和现在一样。
6. **英文词典**补齐，测试覆盖以上组件。

## 内置插件（2026-10-22，姜维川定）
- `apps/server/plugins/official/*` 随服务端包发布（Docker 镜像也带上），**不用再上传**：服务端启动时 `syncBuiltinPlugins` 把每个目录装到平台层，内容没变就不出新版本，代码更新后自动出新版本。
- 内置插件没有编辑人（`updatedBy` 为空），`PluginDto.builtin` 为 true：平台层不能删除，也不能上传同名插件覆盖；团队层、群层可以上传同名插件替换。
- 装好后仍然要群管理员在群设置 → 插件里打开，才在本群生效（叠加能力不变）。
