# v0.4.0

这一版把群内 Git 管理完整升级到 IntelliJ IDEA 级别的查看与操作体验，覆盖提交、历史、比较、分支、合并冲突、贮藏、注解和更多安全写操作。

This release upgrades Git management in groups to an IntelliJ IDEA-style experience, covering commits, history, comparisons, branches, merge conflicts, stashes, annotations and more guarded write operations.

## 亮点 / Highlights

- **Commit 与差异视图 / Commit and diff views** —— Git 标签页按「更改 / 未跟踪 / 冲突」分组展示目录树、状态色和增删行数；支持选择文件提交、修改上一次提交、提交并推送，以及统一 / 并排差异、行号、词级高亮、忽略空白和完整文件。
  The Git tab groups changes, untracked files and conflicts with a directory tree, status colours and line counts. Commit selected paths, amend, commit and push, and inspect unified or side-by-side diffs with line numbers, word highlights, whitespace options and full files.
- **Git Log 与比较 / Git Log and compare** —— 新增带提交图的提交历史、分支面板、文本 / 分支 / 用户 / 日期 / 路径筛选、提交详情和变更文件，以及分支、提交和工作区之间的双向比较。
  A commit graph, branch panel, text, branch, author, date and path filters, commit details and changed files, plus two-way comparisons between branches, commits and the work tree.
- **完整分支管理 / Complete branch management** —— 搜索最近、本地、远程和标签；检出、新建、重命名、比较、合并、变基、更新、推送和删除均可从分支弹窗完成；子仓库、嵌套仓库和附加目录仓库都可选。
  Search recent, local, remote and tag refs; check out, create, rename, compare, merge, rebase, update, push and delete from the branch popup, including submodules, nested repositories and extra workspace repositories.
- **合并冲突、贮藏、注解与历史 / Conflicts, stashes, blame and history** —— 冲突时显示进行中横幅和三方合并工具，可逐块接受两侧或手动编辑后继续、跳过、中止；支持贮藏往返、文件注解和按文件查看历史。
  An ongoing-operation banner and three-way merge tool resolve conflicts by hunk or manual edits before continuing, skipping or aborting; stash round trips, per-file blame and file history are included.
- **受控的安全写操作 / Guarded write operations** —— 新增分支、合并、变基、优选、还原、重置、贮藏、标签和冲突解决等操作；Bot 主人直接执行，其他成员申请主人审批，运行中一律拒绝；危险操作二次确认，受保护的基准分支禁止强推和远程删除，其他强推只允许 `--force-with-lease`。
  Branch, merge, rebase, cherry-pick, revert, reset, stash, tag and conflict actions are owner-direct, member-approval, and refused while a run occupies the directory. Dangerous actions ask for confirmation; the protected base branch cannot be force-pushed or deleted remotely, and other force pushes use `--force-with-lease` only.
- **多仓库与 Bot 身份 / Repositories and Bot identity** —— 所有 Git 读操作和操作记录都带仓库选择；提交、合并、变基等写操作显式使用 Bot 自己的 Git 身份，不会被宿主进程的环境变量覆盖。
  Every Git read and operation record identifies its repository. Commits, merges, rebases and other writes explicitly use the Bot's Git identity instead of inheriting the host process environment.

## 升级须知 / Upgrade notes

- 新增迁移 `0079`：`git_operations` 增加 `args` 列，用来持久保存新操作的参数和审批状态。服务端部署时自动执行。
  Migration `0079` adds `git_operations.args` to persist parameters and approval state for the new actions. It runs automatically with the server deployment.
- IDEA 级别的读写接口需要 Bot 所在机器的 `gg` / 桌面端升级到 v0.4.0。旧版 daemon 会提示「客户端版本过旧」。
  The IDEA-style read and write protocol needs `gg` or the desktop app on the Bot's machine upgraded to v0.4.0. Older daemons are told the client is too old.
- 已安装 v0.2.0 及以上客户端会自动更新。
  Clients on v0.2.0 and later update automatically.
